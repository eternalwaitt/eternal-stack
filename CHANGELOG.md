# Changelog

All notable changes to Eternal Stack are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/), and this project adheres to [Semantic Versioning](https://semver.org/).

## Unreleased

### Added

- Tiered release controls: `scripts/lib/release-controls.mjs` classifies changes as `routine`, `guarded`, or `migration`; `scripts/release-controls-init.mjs` bootstraps committed `.etrnl/release.json`, an env-var release gate, and a telemetry shim in target repos on first use.
- PR and plan gates now assert literal rollback commands and per-path observability for guarded/migration classes via `pr-preflight validate-body` and `plan-readiness-check.mjs` instead of leaving those requirements for deploy-time `etrnl-ops-ship`.
- Release controls auto-bootstrap on first guarded/migration gate in deployable app repos — no manual `release-controls-init` step for users.
- Every execution-ledger event carries an `actor` recording the session bucket it resolved to plus the writing process's pid, ppid, and cwd, so a task or phase written by something other than the current orchestrator is attributable instead of anonymous. Self-reported identity from `--actor` or `ETRNL_AGENT` is kept separately under `actor.claims`, matching the trust boundary `agent-output-contract.mjs` already applies to a self-declared `ETRNL_AGENT`.
- `execution-ledger.mjs reconcile` reports duplicate pointers aimed at one ledger, pointers whose ledger no longer exists, and ledgers whose `sessionId` diverges from the session bucket encoded in their `runId`. `--apply` retires stale pointers into `runs/retired-pointers/` and records each change as a `ledger.reconciled` event; re-running does not restamp a standing finding.
- `scripts/lib/private-strings.mjs` owns private-string detection for tracked artifacts, replacing four independent copies of the same pattern list in `deep-audit-artifact-check.mjs`, `tool-effectiveness.mjs`, `session-deep-dive.mjs`, and `stack-profile-check.mjs`.
- `planned` joins `passed`, `not_applicable`, and `blocked` as an install-proof stage status and requires the gate command in its `command` field, so a plan can commit to the staged install, doctor/canary, and rollback gates it has not run yet and `/etrnl-dev-execute` upgrades each one to `passed` from the execution run.
- `planTouchesInstallSurface()` in `scripts/lib/plan-risk-tier.mjs` reports whether a plan changes an installable surface. The tier-3 auto-escalation list is now split into install-surface patterns (`hooks/`, `scripts/install*.sh`, `scripts/update.sh`) and high-risk domain patterns (auth, payment, money, migration, tenant); their union is unchanged, so escalation behavior is identical.

### Changed

- `etrnl-ops-ship` is a class-aware verifier: it reads plan/PR evidence and the release manifest, confirms PR gate green, and promotes by signal. It no longer originates release-control requirements or blocks deploy with "write a follow-up release-controls PR."
- UserPromptSubmit routing for `etrnl-ops-ship` no longer matches routine phrasing such as "ship this feature change"; explicit rollout/cutover/go-no-go prompts still route ship.
- `pr-preflight` and `plan-readiness-check` auto-bootstrap release controls; users no longer run setup scripts manually.
- `etrnl-dev-execute` is back under the 18,000-byte repo-owned prompt budget (18,705 → 17,897) by stating the source-checkout/installed helper-path convention once instead of spelling both forms per command, and by removing restatements the same file already carried (full-packet schema, reopen-cap disposition, `doctor.sh --changed`, parent-vs-subagent ownership). No rule was dropped.
- `etrnl-dev-autoplan` records install proof as `planned` while planning and `not_applicable` when no install surface is in scope, and declares the risk tier the deterministic gate requires. Escalating above that floor on judgment is still allowed but must be named as a judgment call on the `Risk tier` line rather than attributed to the readiness gate.

### Fixed

- CodeRabbit round 12: Stop-verifier question detection is clause-local so an unrelated `?` in a later sentence no longer suppresses a positive verification claim; UserPromptSubmit read-only questions require execution intent only after the question delimiter and suppress downstream plan-execution re-arming; `bounded-review.md` validates `execution-ledger.mjs` and the selected script root; eternal-saas install backup paths avoid the `mktemp`/`rmdir` reservation race; `cc_json_read_stdin` passes idle-reader config explicitly; `etrnl-dev-pr` compares before copying helpers, gates full-install refresh on owner confirmation, and validates/redacts `FINDINGS_FILE` before ingestion; `review-learn.mjs` rejects sensitive-looking finding text before persistence.
- CodeRabbit round 13: Stop-verifier treats questioned and hypothetical lint/typecheck/checks claims like test/build wording; router extracts execution intent after the final question mark in informational prompts; `review-learn.mjs` defaults the ledger to the private overlay, scans complete finding JSON for secrets, and expands credential patterns; `etrnl-dev-pr` rejects in-repo findings files and allowlists persisted fields; `reset_settings_preserving_user_settings` no longer injects a null `hooks` key; stdin auto-fallback warning markers expire after 60 minutes.
- CodeRabbit round 14: Router suppresses question-only plan-execution prompts; stop-verifier aligns hypothetical/question handling with positive verification phrases; `review-learn.mjs` scans raw string leaves, rejects ledger/HOME paths inside the target repo, and tightens secret patterns; `etrnl-dev-pr` resolves findings files with `realpath -e` and enforces a strict allowlisted schema; reset-settings matches only installed `bash ~/.claude/hooks/cc-*` commands.
- CodeRabbit round 15: Reset-settings hook matching is anchored to command start; `etrnl-dev-pr` optional-field validation rejects non-string present values; router plan-execution clears set suppress before state writes; review-learn rejection tests verify ledger and rules immutability.
- CodeRabbit round 16: Reset-settings matches only `bash ~/.claude/hooks/cc-*` installer commands; router plan-execution suppression survives `cc_state_update` write failures.

- Every hook read its payload to EOF, and Claude Code only closes stdin on the first hook invocation of a session, so from the second invocation onward each hook blocked until its own timeout killed it. Across the 50 most recent sessions, 1,272 of 1,649 `PostToolBatch` invocations — 77% — were cancelled at the 5-second mark having emitted nothing and recorded no state: the first invocation of a session had a 384 ms median and no timeouts, every later one a 5,019 ms median. The observer is what records edits, reads, and `verificationRuns`, so the Stop verifier was gating on evidence the timeout had already discarded. State size was ruled out as the cause; a 3.9 MB production state file runs the hook in 199 ms, and a synthetic 8.6 MB one in 195 ms. `cc_json_read_stdin` now reads with a 100 ms idle timeout through `python3` or `perl` and falls back to the previous read-to-EOF when neither is present, so a held-open stdin returns in about 150 ms instead of never. The threshold is twice the largest inter-chunk gap measured while delivering a 200-tool payload in chunks; the 4 MiB cap, the `{}` fallback, and the `HOOK_INPUT` contract are unchanged. Set `ETRNL_JSON_STDIN_READER` to `auto` (default), `python`/`python3`, `perl`, or `head`/`blocking`/`block` when diagnosing a host where the idle reader misbehaves.

- A default install deleted every user-owned key from `~/.claude/settings.json`. `reset_settings_preserving_enabled_plugins` rebuilt the file from an allow-list of `enabledPlugins` and `statusLine` before merging the hook template, so `permissions`, `skillOverrides`, `skillListingBudgetFraction`, `model`, `env`, and every other native Claude Code setting the stack does not own were dropped on each run — and any attempt to tune one was undone by the next install. `merge-settings.mjs` only ever writes `target.hooks`, so the reset now drops only stack-owned `~/.claude/hooks/cc-*` entries and preserves foreign hook wiring plus every other top-level setting.

- The Stop verifier demanded verification evidence from turns that changed nothing. Its zero-`verificationRuns` gate fired on any completion claim, so a read-only audit that edited no files was told to "run project preflight, verify user-visible behavior" when there was nothing to verify. The gate now requires either recorded edits or a message that asserts verification happened — "tests pass", "verified", "build passes" and similar — so a claim of evidence with no runs behind it still blocks even without edits, while a genuine read-only answer completes.

- `planExecutionRequested` was set but never cleared, so a single "implement the plan" armed the Stop verifier's ledger gate for the remainder of the session and every later turn, including questions and audits, had to satisfy `--require-ledger --require-tasks --require-plan-phases`. A read-only prompt now clears the flag, and execution intent in the same prompt still wins and keeps it set. Separately, the agent-files route matched "agent files" but not "agents files" or "agents.md", so the plural phrasing routed nothing.

- `etrnl-dev-pr` and `references/bounded-review.md` now invoke review helpers through `~/.claude/scripts/` (installed Eternal Stack home) instead of repo-local `scripts/review-learn.mjs`, which is not vendored into application repositories. The PR skill explicitly warns agents not to probe for a repo-local copy.

- The eternal-saas rule pack was loading as global Claude context in every repository. `install.sh` staged both scopes under `~/.claude/rules/eternal-saas/` as source material for `init-project-rules.sh`, but Claude Code auto-loads every `.md` under `~/.claude/rules/` as user-scope memory: the three `global/` modules carry no `paths:` frontmatter so they loaded unconditionally, and `project/stack.md` and `project/local-overrides.md` declare `paths: ["**"]` so they matched every repo. Stack-specific `pnpm ci:check`, `veloz deploy`, and `tenantId` guidance — plus the `local-overrides.md` post-install stub, which addresses the human running the installer — was therefore in context while working on unrelated projects. The pack now stages under `~/.claude/docs/templates/rules/eternal-saas/`, alongside the other install templates and outside the auto-load surface; `init-project-rules.sh` resolves the tracked `rules/eternal-saas` source first and falls back to the staged copy, and install removes the legacy directory after backing it up so rollback still restores it. Only `rules/etrnl/` installs to `~/.claude/rules/`.

- `templates/CLAUDE.md` imported the six `rules/etrnl/*.md` modules with `@`, which loaded each one twice: `@` imports expand at launch and Claude Code separately discovers the same files under `~/.claude/rules/`. The imports are gone and the template records why they must not come back.

- The requested-skill Stop gate could not be satisfied and never expired, so one keyword match blocked every completion claim for the rest of the session. Its message offered two ways out — invoke the skill, or state why it is unavailable — but the check was a plain set difference between `requestedSkills` and `skillCalls` that read no part of the assistant message, so the second option did not exist and repeating the explanation produced the identical block on every turn. `requestedSkills` is also append-only and never cleared, which made a single match permanent. Requests now expire after an hour (an unparseable timestamp counts as expired rather than as a permanent block), and a rationale that both names the skill and says why it does not apply is honoured and recorded in `skillRequestWaivers`, so it is needed once instead of in every later message. A request newer than its waiver blocks again, because that is a new ask; naming the skill with no reason, or giving a reason without naming it, still blocks.

- Two `cc-userprompt-router.sh` matches manufactured skill requests the gate above then demanded be served. `activePlanPath` was set from any slash-bearing `.md` token anywhere in the prompt, so a fragment of a path to a findings document became "the active plan" — and because that field is sticky with no expiry, it stayed armed for the session. The bare-phrase execution branch it guards then matched ordinary conversational replies (`do it`, `finish it`, `carry on`, `implement now`, `execute now`), so answering "push the changes and test? do it" routed `etrnl-dev-execute`. An active plan path must now live in a plans directory and exist on disk, and the phrase list requires wording that names the plan.

- Concurrent sessions in unrelated repositories wrote into one another's run ledger. `init --session "$CLAUDE_SESSION_ID"` resolves an unset variable to `default`, and every pointer, hook, and reporting script resolved that one label to the same machine-wide `current-default.json` — so three projects running at once shared a single ledger, and one project's stop gate evaluated another's phase id. Actor provenance made the collision visible but not impossible. The unnamed label is now qualified by the worktree it resolved from (`default-<worktree>`, keyed on `git rev-parse --show-toplevel`), so cross-project writes cannot address each other at all; an explicitly named `CLAUDE_SESSION_ID` is still honoured verbatim, since sharing one bucket across worktrees can be deliberate. A session already in flight under the old shared pointer keeps resolving through it, but only from inside the worktree that owns the ledger — from anywhere else it reads as "no active ledger" and names the reason. `reconcile` gains a `foreign-writer` finding for ledgers carrying events from another worktree, which is the residual case a shared explicit session id can still produce.

- Four copies of the ledger pointer resolution had drifted apart across `execution-ledger.mjs`, `token-savings.mjs`, `provenance.mjs`, and `hooks/lib/state.sh`, so a scoping fix in one would have left the other three resolving the old shared bucket. They now share `scripts/lib/ledger-pointer.mjs`.

- A tier-3 review loop that spent its four reopen rounds stopped the whole run to ask the user for permission, even when nothing blocking was left open. `references/bounded-review.md` sent every still-open finding at the cap to a repository-owner decision without first checking severity, and it said the wave stops rather than the stream, so a cosmetic P2 could park an entire plan behind a free-text approval request while independent task groups the finding never touched sat idle. The disposition is now mechanical: `review-merge.mjs` emits `capDecision` (`close`, `reopen`, `proceed-with-residuals`, `owner-decision`) from the merged severities plus the cap and park state, `proceed-with-residuals` closes the stream autonomously on every tier including 3, and only a P0/P1 that survived every round — and one `etrnl-investigator` pass — reaches the user, stopping that stream alone. The ledger's reopen-cap error and the `etrnl-dev-execute` ask policy and anti-rationalization table say the same thing at each point an agent could improvise.

- The Stop verifier demanded a re-verification for changes the last green run still described. Its staleness check compared the newest edit of *any* kind against the newest verification, while its sibling quality and test gates already filtered to source paths, so updating a README or changelog after a passing suite blocked completion; `cc_trivial_nonruntime_diff` could not relax it because that fast-path classifies the whole worktree, and any earlier code change or unrelated dirty file keeps it shut. Staleness is now scoped to the paths edited after the last recorded verification, classified through the same `diff-triviality.mjs` taxonomy with the same fail-safe direction, so a runtime change after a green run still blocks.

- Repos whose gates are scripts rather than package-manager tasks recorded no verification at all. `cc_command_is_quality_verification` matched a bare `test` token, which `tests/test-hooks.sh` does not provide, so `bash tests/test-hooks.sh` and `bash scripts/doctor.sh` — the two commands `AGENTS.md` prescribes and the hook's own code-health messages recommend — never reached `verificationRuns`, and the Stop verifier answered a completed preflight with "no verification evidence". Both classifiers now recognize project gate scripts (`tests/*.sh|mjs|py`, `node --test`) and health gates (`doctor.sh`), requiring an executing primary token so that reading or searching a gate script is never counted as running it.

- An edit and a verification recorded in the same second read as "the run came first" and blocked with `missing-quality`. Every state timestamp is second-granular (`date -u +%Y-%m-%dT%H:%M:%SZ`), so exact ties were possible; `editGeneration` and `commandLastEditGeneration` now break them, and only them.

- The stale-verification block named neither the paths that went stale nor the gate that last ran, so the only available response was to re-run every gate in the project. It now lists the changed paths (first five, repo-relative) and the last recorded verification command with its timestamp.

- `cc-compact-suggest.sh` reported a nearly exhausted context window at 16% of a 1M-token session. The hook compared live usage against a hard-coded 200k window, which is correct only for pre-1M model generations — every current Claude generation (`claude-opus-4-7` and newer, `claude-sonnet-5`, `claude-fable-5`, `claude-mythos-*`) has a 1M window — so a session that had used 160k of 1,000,000 tokens was told it was past the 75% compact threshold, and past 200k the advisory printed percentages above 100. The window is now resolved per session from `ETRNL_COMPACT_WINDOW_TOKENS`, the host's `CLAUDE_CODE_MAX_CONTEXT_TOKENS`, a payload `context_window.context_window_size`, then the session model read from the same transcript pass that already reads usage, honoring `CLAUDE_CODE_DISABLE_1M_CONTEXT` and an explicit `[1m]` suffix. Because usage can never exceed the real window, an inferred window below the observed count is widened rather than reported as over budget.

- A stray task or phase written into a run ledger left no trace of its writer, so a blocked stop gate could not be diagnosed. Ledger events recorded only what changed, never who changed it, and two ledger identities were silently conflated: the pointer bucket in `runId` and the owning session in `sessionId`. Because `init --session "$CLAUDE_SESSION_ID"` resolves an unset variable to the shared `default` bucket, unrelated sessions in unrelated repositories could resolve to one another's ledger through `current-default.json` and write ids that never appeared in the plan. Events now carry actor provenance and `reconcile` retires the aliased pointers that make the collision possible.

- `planTouchesInstallSurface()` now evaluates only changed paths extracted from `## File map` and `## Task groups`, so prose references to an installer no longer make a tier-3 plan reject valid `not_applicable` install proof.
- `private-strings.mjs` now detects `file://localhost` private paths and Windows drive paths encoded in file URIs, closing absolute-path forms that bypassed artifact privacy checks.
- `SECRET_PATTERN` now recognizes the `gho_`, `ghu_`, `ghs_`, and `github_pat_` GitHub token prefixes that the shared sensitive-value detector already recognized, keeping direct secret scans aligned.

- Tier-3 plans could never reach `Status: Final`. `validateInstallProof` and `validateRiskTier` demanded `passed` source-gate, staged-install, staged-doctor, and rollback proof before a plan counted as executable, but that proof only exists after the plan runs — so autoplan produced a complete, fully reviewed tier-3 plan and then stopped on `Blocked until <blocker>` for evidence it was structurally unable to hold, surfacing an unactionable error to the user. Tier 3 now accepts `planned` proof at plan time and `not_applicable` when the plan changes no install surface, because the tier-3 trigger list covers auth, money, migration, and tenant risk as well as installers, and staged *install* proof is meaningless for the former. `blocked` still fails the gate, standalone `--artifact` checks still assume an install surface and stay strict, and the Stop-time `missing-install-proof` gate in `cc-stop-verifier.sh` still requires real evidence before completion can be claimed. The deadlock went unnoticed because no tracked fixture exercised a passing tier-3 artifact — the only tier-3 fixture was a negative control.

- Private-string detection no longer reports repo-relative source paths as local filesystem paths. All four copies of the rule tested bare segments such as `/home/`, `/tmp/`, and `/Users/` anywhere in a string, so ordinary paths like `src/components/home/Nav.tsx` and `src/tmp/cache.ts` failed the deep-audit artifact gate. Detection now scans path-like tokens anchored at an absolute root before testing the private roots, which keeps application routes and repo paths clean while still catching POSIX, home-relative, Windows drive, UNC, WSL, and `file://` local paths. A real UI/UX audit artifact was blocked by 15 such false positives with no actual leak present.

## v0.11.1

2026-07-25


### Added

- Both settings templates ship `codegraph prompt-hook` on `UserPromptSubmit`, alongside the existing `rtk hook claude` precedent for third-party tool hooks. Install resets foreign hook entries before merging the stack template, so a hook present only in a user's home was silently dropped on every install; shipping it in the template makes it survive. The entry carries an explicit 10s timeout, matching the convention every other hook in those files follows.
- `scripts/lib/json-file-store.mjs` provides the cross-process primitives every writer of a concurrently-written JSON file needs: a `mkdir`-based lock, `rename()`-backed atomic replace, and a `updateJsonUnderLock` helper that keeps the read and the write in one critical section. Extracted from the lock that `execution-ledger.mjs` already held privately rather than written as a second implementation.
- `scripts/lib/ux-finding-taxonomy.mjs` owns the UI/UX severity and finding-status enums that three scripts previously hand-rolled independently.

### Changed

- The UI/UX finding `status` field is enforced by `deep-audit-artifact-check.mjs` with a new `UX_FINDING_STATUS_INVALID` error, resolving a contract that documented `status` as required in `audit-checks.md` while no validator checked it. Every existing fixture already emitted `status`, so no artifact migration is required.
- The `cc-question-preference.sh` settings matcher covers every ask-tool name the hook itself accepts. The matcher was narrower than the hook, so `mcp__*askUserQuestion*` and `mcp__*user_question*` names were filtered out before the hook could ever see them.

### Fixed

- The documented merge rule for the `promoted` map in `review-learnings.json` is shape-aware, because entries for one class key are not interchangeable. `review-learn.mjs` writes a guard, a precision-blocked checklist candidate, or a plain checklist candidate for the same key depending on whether a corpus was supplied and what precision it measured. Keeping the guard side over a candidate marked `blockedBy: "precision"` installs a guard the precision gate refused, and because a guard entry is only written after its rule is durably in `review-rules.json`, the two files are resolved together.
- `docs/health-stack.md` documents `review-learnings.json` merge resolution field by field instead of as one blanket rule. The previous guidance — union the keys and keep the higher count — held only for `recurrences`. Applied to `promoted` it discards promotion metadata and silently un-promotes a class; applied to `processedReviews` it drops review ids and lets a review inflate the counters twice; applied to `cleanRuns` it is backwards, because `review-learn.mjs` flips a guard from warn to block at `cleanRuns >= 2`, so keeping the higher count escalates a guard to blocking on clean runs neither branch observed.
- Install copies `tests/lib/parallel-run.sh` and `rules-manifest.json` into the installed home. Both are read by the installed test suites, and neither was in the copy list — so `doctor-etrnl.sh` in an installed home failed `test-hooks.sh` on a missing source file and `test-workflow-tools.sh` on a missing manifest. The repo doctor passed throughout because it runs from a tree where both files exist.
- Concurrent writers no longer lose rows from `review-learnings.json`. `review-merge.mjs` and `review-learn.mjs` both did an unlocked read-modify-write on the shared store, so parallel reviewer lanes — the workflow the feature exists to enable — silently dropped each other's rows, and a crash mid-write truncated the store for both. Both writers now serialize on one lock and replace the file atomically. Measured before the fix: six concurrent lanes left one surviving row out of six, and a mixed learn/merge race lost two of four recurrence increments plus two of four reviewer rows.
- Install records newly created files in the rollback manifest, so rolling back no longer leaves stale copies of `tests/`, `tests/lib/`, and `rules-manifest.json` behind on a host that had no prior install. The three hook symlinks pointing into `tests/` are recorded too, since removing their targets without them would leave dangling links.
- The stale-lock reclaim path is far less likely to hand one lock to two processes. A reclaim marker excludes rival reclaimers, and an owner-token comparison refuses the delete when the real owner released and a new acquirer replaced the lock mid-reclaim — previously a reclaimer that had judged a lock dead could delete the fresh lock that replaced it and then enter the critical section alongside its holder. The residual window between the token re-read and the delete cannot be closed, because POSIX offers no atomic compare-and-delete for a directory, so a `staleMs` larger than the longest critical section remains the actual remedy rather than an optimization. A non-numeric `ETRNL_LEDGER_LOCK_TIMEOUT_MS` no longer spins the acquire loop forever either: `Number("abc")` is `NaN`, which compares false against every elapsed time, so a typo disabled both the timeout and the staleness reclaim instead of failing fast.
- `writeJsonAtomic` preserves an existing file's permissions. `rename()` replaces the destination with the temp file's mode, so a store previously at `0600` silently widened to the umask default on the first rewrite by a caller that omitted `mode`.
- `diff-triviality.mjs` no longer shifts File map column indices when a row has a blank Change cell. `filter(Boolean)` dropped the empty cell, so an unrelated column supplied the Change note and could classify a runtime script as non-behavioral.
- `agent-task-packet-check.mjs` reuses the Sol-escalation predicate and canonical model set exported from `codex-model-routing.mjs` instead of re-implementing the regex and hardcoding model names, and `codex-rollout-baseline.mjs` derives its headline model from the same source and recurses into nested subagent spawns instead of counting only direct children.

## v0.11.0

2026-07-25


### Added

- `scripts/ux-inventory.mjs`: UI/UX surface enumerator. Emits the six `ux_*` worklists with counts and sha256 hashes, the coverage axes (viewports, themes, locales, text directions, auth states, data volumes, zoom levels), route/surface/state-cell totals, and a mechanical anti-pattern scan (arbitrary spacing and type values, sub-16px body text, gradient defaults, hard-coded hex, missing alt text, click handlers on non-interactive elements, emoji icons, placeholder-as-label). A UI/UX audit now has a denominator instead of an improvised route list.
- `scripts/ux-audit-check.mjs`: red-capable UI/UX gates. `coverage` fails when dispositioned routes, surfaces, state cells, or axes fall short of the inventory without a `coverageExceptions` reason, and when a report consumes a stale worklist hash; `baseline`, `validate-baseline`, and `trend` persist per-check `uxHealthScore` and severity counts so repeat audits report a delta instead of restating the same shortlist.
- `ui-ux-product` registry check `ux-07-cross-cutting-axes`: theme modes, locales, text direction, auth states, data volumes, and 200% zoom — the axes a route x viewport matrix cannot show.
- `deep-audit-artifact-check.mjs` UI/UX evidence rules: `UX_FINDING_FIELD_MISSING`, `UX_SEVERITY_INVALID`, `UX_NON_FINDING_FIELD_MISSING`, `UX_HEALTH_SCORE_MISSING`, `UX_COVERAGE_INCOMPLETE`, and `UX_QUICK_WINS_MISSING`, with `report.ux-valid.json`, `report.ux-coverage-incomplete.json`, and `report.ux-finding-field-missing.json` fixtures.
- `browser-qa-report.mjs` schema v2 `designEvidence` matrix rows (`category`, `severity`, `note`) plus a `designEvidenceSummary` field, so runtime craft observations reach a UI/UX audit as data instead of screenshot prose.
- `scripts/lib/codex-model-routing.mjs`: single source of truth for Codex spawn routing. `resolveCodexModel({ modelTier, codexModel, codexReasoningEffort, modelTierJustification })` returns a `{ model, reasoningEffort }` pair — `fast` → `gpt-5.6-luna`/low, `standard` → `gpt-5.6-terra`/medium, `top` → `gpt-5.6-terra`/high — resolving packet fields first, then `ETRNL_CODEX_MODEL_<TIER>`, then the static map. It throws instead of falling back to inherit, and allows `gpt-5.6-sol` only when `modelTierJustification` names an integration-owner or adversarial escalation.
- Deep-audit lane model routing: every lane across `ui-ux-product` and `performance` now declares a `modelTier` through a lane factory that validates it when the registry loads, so a lane cannot be constructed without one. New `resolveLaneDispatch(lane)` and `categoryLaneDispatch(categoryId)` exports return the explicit model and reasoning effort for a lane spawn; the eleven lanes resolve to seven at `gpt-5.6-terra`/medium and four at `gpt-5.6-luna`/low, with none inheriting the parent thread. A registry test iterates categories dynamically so a future category cannot reintroduce inherit. `CATEGORY_REGISTRY_VERSION` is deliberately unchanged, because lane `modelTier` is dispatch metadata and lane receipts are unaffected.
- `execution-ledger.mjs history --gates [--json] [--plan <path>]`: a gate checklist that replaces time-based progress. It reports `tasks=<done>/<total>`, `phase`, `phaseStatus`, `workstream`, `uatGate`, and `uatOpenFindings`, then `planStatus`, `nextGate`, and `nextGatePhase`; without `--plan` it reports `planStatus=not-provided` and still exits 0. New `record-trajectory --wave <id>` persists `recurringFindingCount`, `streamAlternationCount`, and `roundsSinceProgress` into a `waves[]` array as absolute values that merge on update.
