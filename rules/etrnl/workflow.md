# Workflow

- Use the Eternal router to resolve the task intent, impact scope, consequence risk, and whole-task budget explicitly. Its validated contract is the only source for mandatory phases, task records, packets, verification evidence, review, and delegation limits.
- Keep the user’s full requested outcome. A plan is a handoff, not authorization for new external effects. Continue routine reversible work within standing authorization; stop only for a material blocker, a real project approval gate, or an action outside the grant.
- Use `etrnl-dev-brainstorm` when requirements need shaping; `etrnl-dev-plan` or `etrnl-dev-autoplan` when a written plan will help or the contract requires program phases; `etrnl-dev-execute` for authorized implementation. Direct contained work does not need an imposed plan or ledger.
- Load capability guidance only when it is relevant or the contract requires it. Available, loaded, and mandatory are separate states. Host hooks, agents, and other integrations are active only when configured and confirmed by that host.
- Preserve unrelated changes, verify the changed behavior with relevant repository checks, and report actual evidence and any remaining gap.
- Use `etrnl-audit-code` for a whole-codebase health review when requested. Use browser or context save/restore capabilities when their evidence or continuation state is part of the task.
- Keep chat summaries short when the durable result is a file.
